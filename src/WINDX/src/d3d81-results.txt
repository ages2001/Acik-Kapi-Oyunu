Direct3D 8 and 8.1 programmable rendering
=======================================

Run wxd3d81.exe beside the WINDX d3d8.dll and the selected WINOGL renderer.
The test creates a Direct3D 8 device with programmable vertex processing and
an A8R8G8B8 lockable render target. It compares all twelve pixels after clearing
the target and after each draw.

Shader cases
------------
VS 1.1 transforms clip-space positions with a vertex shader constant.
PS 1.1 paints the triangle with a pixel shader constant.
PS 1.2 reads a second texture using RGB coordinates from the first texture.
PS 1.3 writes a depth of 64/191 using texm3x2pad/texm3x2depth. The rendered
geometry passes a 0.4 depth threshold and fails a 0.25 threshold.
PS 1.4 performs an actual second texture lookup after phase and masks the red
channel of the sampled texel. Independent texture samples verify both inputs.

Windows x86 softpipe
--------------------
Direct3D 8 selects 24-bit x87 precision during normal device creation. On
Windows Me, the previous Mesa texel rounding calculation incorrectly selected
the lower-right palette entry for UV (191/255, 64/255). Keeping the original
application precision with D3DCREATE_FPU_PRESERVE isolated the cause. The
project now obtains integer floor by truncating and correcting negative
fractions on 32-bit Windows. The following test runs use the default Direct3D
floating-point behavior. The test does not request D3DCREATE_FPU_PRESERVE.
