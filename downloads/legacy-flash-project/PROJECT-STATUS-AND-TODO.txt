2. REQUESTED GOALS

- Fully port the original FP10 and FP32, not replace/rewrite the Flash engine.
- Prioritize NT3.1 and SM63, then NT3.5x/NT4, Windows95/98/ME and Windows3.1x
  with Win32s. Test in QEMU, using copies of the supplied OS disks.
- Fully functional sound, video, graphics, input, menus, buttons and saved games.
  No missing-API aborts, visual corruption or unexplained application errors.
- Acceptable software rendering speed. Optional GPU acceleration when the
  OS, driver and graphics API actually support it; do not require DirectX on
  systems that cannot provide it. Use WINVBE where useful, then check classic
  VGA on each OS at the end.
- One FP10 executable that uses SSE2 when both hardware and OS state handling
  permit it, otherwise uses non-SSE2; show the active mode in About.
- FP32 should keep SSE2 unless a practical non-SSE2 adaptation is established.
  About should show SSE2; startup failure should recommend Flash Player 10.
- WINSIMD support for OSes lacking context preservation, including multiple
  processors. Deliver the 1.2 source/binary ZIP and an English changelog.
  Correct XMM handling; do not mistake CPU-feature enabling for YMM/ZMM saving.
- Retry/fix the NT3.1 MP HAL/kernel patch using the supplied newer NTLDR and
  NTDETECT.COM, in a copied disk. Deliver corrected source, binary and explanation.
- A single setup file per product across target OSes; Next/Back wizard, editable
  destination, visible progress and no white-rectangle GUI artifacts.
- FP10 defaults: C:\FP10 on NT3.xx/Windows3.1x; C:\Program Files\Flash Player 10
  on Win95/NT4 and newer. The later FP32 request changes its default folder name
  to FP32; the current NT3.1 installer uses C:\FP32. Final other-OS path behavior
  remains part of the unfinished universal installer work.
- Create program and uninstall shortcuts, a red-cross uninstall icon, automatic
  .swf association and reliable double-click launching on every target OS.
- Use the original projector icon; FP32 should use the supplied dark-red style.
- About attribution: "Ported to Windows NT3.1/3.5x/4 , Windows 95/98/ME and
  Windows 3.1x with Win32s" and "Ported by ages2001". Attribution is not a test pass.
- Save correctly on every OS, including systems without AppData. Preserve user
  data during updates and handle uninstall/save retention deliberately.
- Test SM63 first, including Start, file selection, movement, coins and the first
  castle save. Then test Final Fantasy Sonic, MMS RPG, Sonic RPG Episode 10,
  Megaman X Virus Mission, Takeover and the other supplied SWFs.
- Use original-binary analysis/REA where helpful to implement compatible DLLs.
- All project text/code/UI in English; conversation in Turkish. Provide visible
  screenshots, honest progress counts, downloadable ZIPs and repository copies.

3. COMPLETED / MEASURED WORK

Player infrastructure and CPU handling
- Adapted original FP10 and FP32 executables, compatibility DLLs, launcher/build
  scripts and native diagnostic tests are present. Unknown imported calls remain
  explicit diagnostics; success has not been fabricated to hide missing behavior.
- FP10 has one executable with automatic CPU-mode selection and About labeling.
  Its earlier installer/CPU-mode test exercised an NT3.1 Pentium II without SSE2.
- FP32 retains an SSE2 gate with OS context-readiness checks. The readiness fix
  addresses the previously false CPU feature report associated with the SM63
  Star Coin overlay; it does not certify all SM63 logic or all processor models.
- Original icon integration, About attribution and private save storage exist.

Native compatibility components
- Current FP10/FP32 mixer implementations passed 40 checks per player per NT3.1
  and NT3.51. Native playback controls, callbacks, volume changes/restoration and
  native wave-handle translation are covered. Not all audio paths are covered.
- The early-NT timer ABI bridge passed 18 checks on NT3.1 and 17 on NT3.51.
- ANSI version verification passed 20 native checks per OS.
- Number/currency formatting passed 1,350 reference comparisons per player per
  OS on NT3.1/NT3.51. NT3.1 NLS input capture allows a like-for-like comparison
  with the original NT3.51 formatter despite different OS locale data.
- Each player additionally passed 25 formatting contracts on NT3.1 and 19 on
  NT3.51, including large decimal rounding, modern grouping, Unicode symbols,
  parameter validation, and NT3.1 user-override restoration.
- FP10 Winsock create/close event support passed 19 native checks per OS.
- Earlier component work covers documented file/save handling, heap locking,
  memory queries, thread/affinity, GUID/string operations, legacy cryptography,
  software alpha blending, timezone conversion and other adapters. Consult the
  raw reports for each component's exact limitations; these are not blanket passes.

SM63 gameplay/save evidence
- The original SWF reached gameplay with the original adapted FP32 engine.
- A prior gameplay candidate obtained the first Shine, saved, reopened the player
  and loaded the save again after a normal Windows restart.
- The preceding combined 87/53 runtime loaded File A, accepted movement/jump and
  pause/exit, copied A to B through the game's menu, and loaded B after player
  restart and normal Windows reboot. File A stayed unchanged; File B matched A.
- The 5,730-byte save after Copy/player restart/OS reboot matched SHA-256
  4f45ad24ed6aaf89f5c6b879550a2f00ace9203043fc28db673de4af1e979c5b.
- No SWF/save variables were edited to prove persistence; no VM migration restore
  was counted as a Windows-reboot save test. Tests used separate disk overlays.
- Actual loaded DLL paths/CRCs were checked. Initial display: WINVBE 800x600x32.
  Later native probe: Vga 640x480x4, 16 colors after a real driver change/reboot.
  The earlier unmeasured 800x600x4 VGA claim was corrected in published status.
- Nonzero stereo AC97 PCM was captured from the SM63 session. This is not proof
  of every effect, the precise Runouw track, all video paths or A/V synchronization.
- The latest three functional DLL changes (FP10 FPK/FPW and FP32 F32K) have native
  component coverage but SM63 has NOT been replayed with them. Other runtime
  differences from the preceding package are PE timestamps/checksums only.

Installers
- Wizard, path selection, progress, icons, shortcuts, associations and uninstall
  source are present. Earlier NT3.1 installer tests cover the documented subsets
  of installation, association restoration, unrelated-file and save retention.
- This handoff rebuilds SETUP10-DEV.EXE and SETUP32-DEV.EXE with the latest binaries.
  All 18 FP10 and 26 FP32 payloads match BIN byte-for-byte; embedded CRC/SHA-256
  checks pass. Their native GUI/install/uninstall tests were NOT repeated after
  this rebuild. They are development installers, not universal OS installers.

WINSIMD and NT3.1 MP patcher
- Research XMM0-XMM7/MXCSR preservation exists for the documented exact NT3.1
  UP/MP kernels. Native x87 preservation was checked alongside it.
- Recorded one-CPU/four-CPU worker, affinity-migration and thread-churn tests
  passed in their documented configurations. The query-aware driver supports
  the FP32 startup readiness protocol; native UP/MP query checks are recorded.
- This remains research code with a 512-entry table and an unresolved all-CPU
  installation rendezvous. It is not a final WINSIMD 1.2 production release.
- NTCPUPAE r2 fixes the observed NT3.1 sparse-PFN failure with the supplied newer
  loaders, preserves original files/first loader backups and adds the guarded
  MP boot entry. The rebuilt GUI was tested on copied VHDs; four CPUs, mask0xF
  and a successful worker thread were measured. The PFN guard passed 320 cases.
- These results apply to the exact validated kernel/HAL/loader configuration;
  they do not establish arbitrary ACPI/MPS support or new bare-metal coverage.

4. REMAINING WORK / ACCEPTANCE GAPS

- Resolve the 49 FP10 and 85 FP32 diagnostic imported API gaps listed below.
  Some can stop an SWF when reached. They are not all harmless or proven unused.
- Complete partial adapters and dynamic APIs even when the import count reaches
  zero. A zero stub count alone would not establish a completed player port.
- QueueUserAPC remains unresolved: supplied NT3.1/NT3.51 NTDLLs do not export
  NtQueueApcThread; a simple forwarder cannot supply the missing kernel facility.
- Finish timer/fiber/threading, window/menu/input/font, shell/clipboard/OLE,
  networking/HTTP/certificate, color-management and remaining media behavior.
- Experimental NT4 DirectSound playback probes produced real tones, but the
  provider stays disabled: modern buffer descriptors/options, GLOBALFOCUS and
  capture are unresolved. Capture/MIDI/other audio devices remain unverified.
- Legacy crypto does not supply modern AES providers or SHA-256. Software alpha
  blending has documented unsupported bitmap cases. Unknown NT3.1 negative-
  number locale defaults are rejected instead of guessed; not all localized
  NT distributions or custom NLS installations are certified.
- Replay SM63 with the latest three DLL changes, then fully validate its menus,
  input/hover timing, coins, progression, save/delete/copy and restart behavior.
- Classic VGA visibly has wrong colors. Software QEMU gameplay observed around
  6-7 FPS is below the requested performance goal. A two-second hover settling
  interval used by the test is not an input-lag fix. GPU acceleration is unproven.
- Complete actual FP10/FP32 playback integration on NT3.5x/NT4/Win9x/Win32s.
  Win32s threading remains unimplemented. Native NT3.51 component passes are
  not proof of FP32 gameplay on that OS.
- Complete the full game regression suite, all sound/video paths and each OS's
  save/reopen/reboot tests, including the supplied NT3.51 disk-file copy scenario.
- Finish universal installer OS detection/default paths, path-with-spaces support,
  all shortcut/association/uninstall behavior and clean GUI rendering on each OS.
  Current NT3.1 FP32 Program Manager path limitations remain documented.
- Validate final original-icon colors, especially classic VGA, and all application
  menus/buttons. Perform final classic VGA tests on every target OS.
- Finish robust WINSIMD installation synchronization, broader kernel/OS and SMP
  validation. Transparent YMM/ZMM/opmask state preservation is NOT implemented.
  CR4/XCR0 feature enabling does not replace context-switch preservation.
- Recheck package/install/game behavior together before any release claim.

6. USE / REBUILD NOTES

Keep each BIN/FP10 or BIN/FP32 tree intact. Start BIN/FP32/FP32.EXE; retain its
APP/FP32.EXE engine. Do not mix player DLL sets or replace system DLLs with them.
Preserve the full existing UserData/name-map tree and installation root: moving
the player to another root selects a different private save tree on these ports.

For the documented NT3.1 FP32 experiment, use BIN/WINSIMD/NT31-XMM-QUERY, not the
older inherited general-driver binaries. LOADXMM expects XMMGUARD.SYS in C:\FP32;
it logs GUARD.LOG there. GUARDQ reports readiness. Reboot before replacing a
running guard. Exact-kernel checks and the research limitations still apply.

Development installers have fresh payload checks but no fresh native GUI pass.
Use copied test installations while validating the outstanding installer work.
Read the NTCPUPAE and WINSIMD READMEs before applying kernel/driver changes.

The source snapshot retains the working directory structure. To reconstruct
inputs, overlay BUILD_INPUTS/PLAYER onto SRC/PLAYER and set FP10_ORIGINAL to
BUILD_INPUTS/FLASH10-ORIGINAL.EXE. FP32's locator also accepts FP32_ORIGINAL.
Some scripts retain /workspace/fp10-port or historical attachment paths; adjust
those or recreate the documented workspace layout. Generated build metadata,
analysis inputs and experimental sources are retained for continuation.
Required external tools include Python3/pefile, Clang/LLD19, NASM, MinGW headers
and import libraries; QEMU/mtools and the user's OS images are needed for tests.
REA/Ghidra and other analysis-tool installations are not bundled.
